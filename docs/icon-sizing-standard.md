# Icon Designer sizing standard

This document is normative for every dimension control and rendered icon surface in the Icon Designer. Menu-bar icons, Dock icons, the live preview, and source fallbacks use the same resolved scene and the same sizing semantics.

## Control standards

| Element | UI value | Interactive range | Step | 100% / baseline | Persisted renderer scale |
| --- | --- | --- | --- | --- | --- |
| Center content: text, SF Symbols, fallback symbols, imported images, and network primitives | Visible-size percentage | 100–180% | 5 percentage points | 31.1 design units is the nominal design baseline; the 100–180% range follows the legacy Wi-Fi optical-size curve, not a promise that every final raster has a fixed 31.1-unit height | `CenterAppearance.normalizedSizePercentage`; renderer applies shared legacy-Wi-Fi optical calibration at the final output CTM and anchor pixel phase |
| Outer ring stroke | Relative stroke percentage | 80–120% | 5 percentage points | 100% is the legacy regular stroke, raw scale 1.25 | Existing `strokeScale` field; 80% maps to 1.0 and 120% maps to 1.5 |
| Footer arc/dots stroke | Relative stroke percentage | 80–120% | 5 percentage points | Same regular 1.25 baseline as the outer ring | Existing `strokeScale` field; shares the outer-ring policy |
| Outer battery text | Relative text percentage | 90–110% | 5 percentage points | 100% is `BatteryIconOptions.defaultTextScale` (1.8) | Existing behavior `textScale`, multiplied by the percentage |

The center range and nominal 31.1 design-unit 100% baseline are owned by `IconCenterSizingPolicy`; final-raster optical calibration is shared across center sources and keyed by output transform and anchor pixel phase. Stroke range, conversion, and retained storage bounds are owned by `IconStrokeSizingPolicy`. Do not add per-source UI ranges or point-size multipliers.

The optional AirPods glyph in the dual-ring top gap is not center content and has no size control. Its visible height and anchor use the existing battery top-indicator calibration (`batteryTopIndicatorHeight` and `batteryTopIndicatorCenter`), with official SF Symbol ink centered through `drawOfficialSymbol`. It must not inherit the center `normalizedSizePercentage` or the center symbol's 38-point baseline.

When that glyph is enabled, the dual-ring cutout uses the same 64-design-unit **arc length** as the Mac battery value gap (`batteryValueTopGapWidth`). Battery converts this arc length to a progress fraction over `batteryRadius * batterySweep`; AirPods converts it to the corresponding angular gap using `gapLength / batteryRadius`, without the legacy 24-unit AirPods clamp. With the glyph disabled, AirPods retains its existing 18-unit gap and 16–24-unit bounds. The left/right ring start anchors and the normalized 0–1 progress behavior stay unchanged; the wider cutout leaves the calibrated top marker clear on menu-bar and Dock surfaces.

## Center rendering semantics

- The explicit center size is an element-wide setting. Switching between primary and fallback sources, or between battery text, Wi-Fi/SF Symbols, Bluetooth targets, input-source icons/labels, imported assets, and wired/temporary/shared network marks, retains the same percentage. The input-source path follows the centre size control for its icon file, short-label text, and keyboard fallback alike; the label is ink-anchored to the slot centre at every scale (`Issue30WiFiAlignmentTests.testInputSourceLabelInkKeepsTheSlotCentreAtEveryScale`).
- The 31.1 design-unit value is the nominal 100% design baseline, not a fixed physical height for every output. The 100–180% control follows the legacy v1.4.0 Wi-Fi optical-size curve, calibrated at scales 1.0 and 1.8 across menu-bar and Dock rasters; final size is determined by the shared legacy-Wi-Fi optical target at the output CTM and anchor pixel phase. Normalized sizing uses a canonical neutral raster/reference: alpha-128 bounds for raster-backed content, stable `100` text, or variable-symbol value `1.0`. Network primitives also render from canonical neutral geometry rather than cached static geometry bounds.
- Once the user explicitly edits center size, all center sources render from a canonical neutral base/reference before applying the shared percentage; the prior raw per-source scale no longer changes size across source switches. Calibration measures the canonical reference at the actual output CTM and anchor pixel phase, then applies one cached shared multiplier. For live SF Symbols, rendered width, height, and offset are multiplied by that same multiplier; live glyph alpha bounds do not trigger per-glyph renormalization. Thus a weak-signal symbol that draws fewer arcs naturally has a smaller alpha height, while its fixed-reference drawing multiplier remains unchanged. If the field remains absent, the renderer preserves each source's historical scale and rendering path exactly.
- Variable SF Symbols are calibrated from their full/reference variant at variable value 1.0, not from live RSSI/volume values. Live values can change glyph appearance but do not change the cached reference multiplier or cause live-alpha-bounds renormalization. Symbol reference rasters use alpha-128 bounds and a bounded cache of 256 scale entries; template rasters use a bounded cache of 64 entries. Asset fallback sizing and drawing share the same resolved fallback symbol. Asset metrics are keyed by standardized URL, modification time, and file size; primitive canonical templates use their neutral reference rather than live geometry bounds.
- Preserve visible-ink horizontal centering. In particular, SF Symbol side-bearing compensation remains anchored to `StatusIconGeometry.artworkCenterX`; sizing changes must not loosen the Issue #30 ink-centering tests.
- Pairwise renderer tests compare actual ink extents for center text `8`, `80`, and `100` against Wi-Fi and a Bluetooth audio glyph on menu-bar, preview, and Dock outputs. Transparent menu-bar/preview rasters use alpha bounds; the opaque production Dock tile isolates the white foreground glyph. The only tolerance is two output raster pixels (converted back to design units when needed); this accounts for raster-edge quantization rather than accepting a source-specific size rule.
- Aspect ratio is preserved. A wide symbol or asset may exceed the ring width at 180%; do not silently reduce its height, cap the user's maximum, or make scale depend on current battery digits. Ring overlap at the largest size is an accepted tradeoff.
- The same semantic marker is part of `CenterState` equality/hash through the resolved center payload, and therefore participates in Dock render identity. Keep the value on primary and fallback-resolved center payloads. Final-raster calibration measures the canonical neutral reference (alpha-128 raster bounds, `100` text, or variable symbol value `1.0`) at the real output CTM and anchor pixel phase, then draws live content and tint with the cached shared multiplier. The 31.1 value remains the nominal design baseline; 100–180% denotes the legacy Wi-Fi optical-size curve and its equivalent output sizing, not a constant 31.1-unit physical result for every glyph. Raster quantization may make the pixel ratio slightly nonlinear, while aspect ratio remains unchanged.

## Compatibility and edit behavior

- `normalizedSizePercentage` is optional. Its absence means legacy rendering, with no automatic migration when the designer opens, no read-time defaults write, and no reset of visible old values.
- `effectiveSymbolScale` remains the legacy absolute raw renderer scale. `normalizedPercentageScale` remains the legacy Wi-Fi/battery normalized value with its historical source-specific behavior. Old payloads that omit the new field decode as `nil`; unknown new optional data is ignored by older decoders.
- The legacy `normalizedPercentageScale` renderer conversions remain frozen at `28/31` for percentage text and `28/34` for Wi-Fi. They are independent of the 31.1-unit 100% optical baseline for the newer `normalizedSizePercentage` control; do not recalculate them when calibrating the new shared baseline. A `nil` new field continues through the original raw-scale renderer path.
- Reading a legacy value only projects it into the new slider's bounded knob. It must not mutate configuration. The displayed legacy percentage remains derived from the saved legacy value, even when it lies outside the new interactive range. An explicit user edit writes `normalizedSizePercentage`; that new field then takes precedence for every center source while the old fields remain intact for compatibility/rollback. Do not rewrite those historical fields during display or source switching.
- Opening an existing configuration with a missing `normalizedSizePercentage` leaves it absent and preserves legacy rendering. Explicit **Reset Center** or **Reset All** in the designer is a user edit: it sets the center's shared visible-size percentage to 100%, so switching between network, Bluetooth, and other center sources keeps the same baseline. Reset history remains undoable; undo restores the prior legacy `nil` field. The low-level `IconAppearanceConfiguration.resetting(.center)` helper is not the designer reset operation and may retain its classic `nil` marker. Simulation values remain in-memory and never affect settings persistence.
- Existing outer/footer stroke storage remains bounded to 0.5–2.5 during normalization. Existing finite values are not changed merely by opening the designer. The narrower UI is a projection; only an explicit edit stores a value mapped through the standard.

## Acceptance decisions

1. Center Bluetooth audio and non-audio targets use the same visible-size standard as every other center source; audio behavior controls do not own a separate dimension control.
2. Primary and fallback content use the same center percentage. No fallback-only branch may bypass the normalized-size marker.
3. Outer ring and footer strokes use the same 80–120% policy with exact legacy light/bold endpoints and continuous 5-point steps.
4. UI labels are percentages, not raw `×` multipliers. Historical values are preserved until an explicit edit; knob projection never silently rewrites them.
5. Both appearance controls and renderer policy are shared rather than duplicated per source. Tests cover coding compatibility, normalization, reset/undo, cache identity, primary/fallback source resolution, measured rendering across text/symbol/image/primitive content, and strict Wi-Fi ink centering.
6. Pairwise glyph-size evidence is based on actual rendered alpha bounds, with the menu/preview/Dock test tolerance derived only from two raster pixels at each tested output scale; imported image decode and alpha metrics are shared between size measurement and drawing and invalidated by URL, modification time, and file size.
