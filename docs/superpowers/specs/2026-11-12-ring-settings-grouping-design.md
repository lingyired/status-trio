# 顶部圆弧设置分组统一（方案 A）— 设计

日期：2026-11-12
范围：`Sources/StatusTrioCore/UI/Settings/AppIconRingView.swift`（纯视图重组）
状态：待确认

## 意图与为什么

「顶部圆弧」页三种来源（本机电池 / AirPods / 系统监控）的分组位置、命名和顺序目前不一致：本机电池的顶部标记行混在「外环内容」选择器卡片里，尺寸行在「进度」卡片；AirPods 把顶部符号和尺寸塞在唯一卡片里；系统监控的「顶部标识」组排在「圆弧」之后。用户希望把「顶部标识」统一提到每个来源的第一顺位，并把「顶部标识大小」固定在该组最上面，同时让三种来源的分组顺序/命名尽量一致。

## 目标

- 外环内容选择器保持在最上方。
- 每个来源的第一张卡都是「顶部标识」；卡内第一行固定为「顶部标识大小」（共享标准，已实现）。
- 其余分组统一顺序：圆弧 / 进度 → 颜色 → 其它（本机电池=动画、AirPods=回退、系统监控=高级）。
- 控件绑定与行为完全不变，只调分组归属与顺序。

## 非目标 / 反目标

- 不改任何持久化 schema、mapper、渲染器、尺寸算法。
- 不改变顶部标识以外的设置项语义。
- 不为「统一」而制造无内容的空卡片。

## 约束

- 复用现有 `SettingsGroup` / `SettingsRow` / `topMarkerSizeRow`，不新造控件样式。
- 保持 macOS 13 兼容（仅 SwiftUI 视图重组）。
- 本机电池「顶部标识大小」仍受 `isBatterySymbolSizeEnabled` 约束（无可见标记时不需要）。
- 开发者「无电池模拟」开关继续留在「外环内容」卡片（仅 DEBUG 显示）。

## 考虑过的做法

- **A（采用）按来源各渲染、统一顺序与标题。** 改动集中在 `AppIconRingView`，复用共享尺寸行，风险最低。
- B 抽共享 `TopMarkerSection` 组件：一致性更强但引入参数化抽象，改动/评审面更大，收益主要是代码层。
- C 只调顺序不改分组边界：省事但达不到「分组统一」。

## 具体分组（最终）

外环内容（选择器）之后：
- **本机电池**：顶部标识（尺寸在最上 → 电池供电/充电/接通电源/无电池 标记）→ 进度 → 颜色 → 动画。
- **AirPods**：顶部标识（尺寸在最上 → 显示 AirPods 顶部符号）→ 圆弧（左右双圆弧）→ 回退（无 AirPods 回退本机电池环）。
- **系统监控**：顶部标识（尺寸 → 顶部标识内容 → 顶部指标）→ 圆弧（布局/主指标/右指标）→ 颜色（模式/左/右弧颜色）→ 高级（各指标范围与阈值、恢复默认）。

## 留给实现者的判断

- AirPods 无颜色设置（固定蓝/前景色），因此**不放空的「颜色」卡**；顺序视为 顶部标识 → 圆弧 → 回退。
- 本机电池第二张卡标题保留「进度」（其内容为百分比/充电指示/临界阈值），AirPods/系统监控用「圆弧」；顺序一致、标题按来源语义保留。
- 若现有 `SettingsViewTests` 对分组数量/顺序有断言，按新结构同步更新（属预期结构变化，不削弱断言）。

## 验证

- 手动：三种来源逐一切换，确认卡片顺序、顶部标识尺寸行位置、所有开关/滑块绑定不变。
