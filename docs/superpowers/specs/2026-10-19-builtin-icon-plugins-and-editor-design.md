## 1. 本轮目标与范围

用户已明确：外环、中心和底部现在可以独立配置。本轮首先把内置数据源改成插件结构，为以后开放外部安装准备，同时优化当前图标设计器的编辑操作。第一版不提供外部插件安装。

成功标准：内置内容通过统一入口注册；内容选择、运行时解析、预览依赖、监控需求及编辑能力读取同一注册信息。用户能够明确知道正在编辑哪个元素、编辑哪项内容，以及此刻真实显示的是哪项内容。

## 2. 路线选择

| 路线 | 获得的能力 | 判断 |
| --- | --- | --- |
| 只把来源名称和菜单集中到一个表 | 编辑器来源列表统一；运行时仍到处按来源分支 | 不满足本轮插件化目标 |
| 编译进应用的内置内容插件，统一注册与解析，兼容现有存储 | 实际渲染、编辑器和预览共用扩展边界 | 推荐本轮采用 |
| 同时开发外部包加载、脚本执行和新配置格式 | 用户可安装第三方扩展；范围和兼容成本显著增加 | 留给后续独立设计 |

本轮的插件是应用内可注册模块，不是动态加载的 Swift 二进制。面向用户继续使用“内容”“显示方式”“不可用时”等产品用语，不在普通编辑流程暴露注册器或协议名称。

## 3. 插件边界

### 3.1 三层职责

1. **内容插件**：声明稳定 ID、名称、本轮可用位置、呈现类型、适用设置、样例依赖与监控需求；根据输入快照生成既有可渲染状态或不可用原因。
2. **宿主组合规则**：决定首选/备用来源、处理网络异常临时替换、产生解析说明，并应用共享外观。
3. **现有渲染器**：接收同一 scene，分别绘制菜单栏、编辑预览和 Dock，继续执行可见墨迹居中和统一尺寸规范。

插件不直接读写 SettingsStore、不在渲染期间读取设备、不自行开启监控或定时器。输入快照和时间由宿主提供。来源不可用必须返回原因，不能返回看似有效的零值。

### 3.2 注册内容

建议的逻辑分组为 Mac 电池、AirPods 电池、网络、输入法、蓝牙设备和系统音量。Mac 电池在外环提供电量环，在中心提供百分比；蓝牙设备内部区分当前音频输出、指定设备与旧固定图案。用户层保留统一蓝牙入口。

模块可声明多个适用位置及呈现方式；本轮仅注册已实现的组合，不为占位而开放新的可选内容。“无”属于宿主的隐藏元素操作；旧 automaticLegacy 与固定图案通过兼容适配器解析，不重新作为新选项提供。

注册器必须真实参与以下链路：

- 编辑器的来源筛选、来源名称与可编辑能力。
- 首选和备用来源的可用性判断及状态生成。
- 模拟面板的数据依赖聚合与样例编辑入口。
- 蓝牙等监控的需求聚合与释放。
- 同一条解析结果进入菜单栏、Dock 和设计器。

不能保留一个供 UI 使用的“插件目录”，实际渲染却绕过它继续使用独立来源分发表。

### 3.3 技术落点

建议在 `Presentation/Icon/Plugins/` 放置描述、注册、解析契约和内置模块。类型命名可采用 `IconContentPlugin`、`IconContentPluginDescriptor`、`IconContentPluginRegistry`；名称不是外部公开 API。

注册表区分插件 ID 与呈现 ID。同一 Mac 电池插件可提供 ring 和 percentage 两种呈现，不能仅凭来源名称推断绘制方式。目标设备身份仍使用当前归一化地址策略，不进入可见状态说明。

保留类型明确的外环/中心/底部状态，禁止任意类型字典一路传到 renderer。首选/备用选择在宿主统一完成，插件的可用性与内容生成采用同一份输入，避免两次解析产生不同判断。

`IconCompositionResolver` 负责组合与全局规则；现有 `OuterRingResolver`、`CenterResolver`、`FooterResolver` 的来源专属生成逻辑逐步移入内置模块或被模块调用的纯映射函数。既有 palette/尺寸/蓝牙目标逻辑通过适配层复用。

SwiftUI 编辑视图由 UI 层按已注册的编辑能力组装；插件描述和纯解析层不依赖 SwiftUI。设备选择、网络显示规则和 AirPods 布局等专用视图可以保留，不在本轮建设通用表单脚本引擎。

### 3.4 配置兼容

第一版保留 `IconConfigurationV1` 及其已有字段，用一个明确的兼容映射把 RingSource、CenterSource、FooterSource 转换为插件/呈现绑定，并集中处理反向写入。

打开窗口、读取注册器、切换元素或打开模拟面板不迁移或重写偏好。旧来源、尺寸、颜色、设备绑定和回退行为保持可解码。用户明确编辑时仍通过现有事务和撤销路径保存。

这个阶段不宣称“任意未来插件 ID 已可持久化”。外部安装前需单独设计版本化绑定配置和未知插件保留机制。本轮新加内置来源若超出现有 V1 表达范围，仍需要兼容映射和存储适配；注册器不掩盖这项限制。

注册失败、重复 ID 或错误位置不能静默覆盖。查找失败按不可用处理，保留原配置并给出可解释的状态。

## 4. 编辑界面

### 4.1 继续使用双栏

左侧保持菜单栏尺寸、可点击的大预览和 Dock 对照；右侧独立滚动。元素切换始终可达，不随右侧长表单滚走。标题明确显示“编辑外环”“编辑中心”或“编辑底部”。

示意结构：

```text
左：预览                              右：编辑外环
实时数据 / 编辑预览数据…              [外环] [中心] [底部]
菜单栏实际尺寸
                                      内容       AirPods 电池 [更换]
大预览（可选三个元素）                 设备       我的 AirPods
                                      显示方式   左右双圆环
当前显示：Mac 电池 · 80%              顶部图标   开
AirPods 未连接，已使用备用内容
                                      外观       颜色 / 描边粗细
Dock 预览
                                      ▸ 不可用时：显示 Mac 电池
                                      ▸ 提醒与切换

                                      撤销       还原外环…   更多
```

这是结构示意，不改变现有真实几何，也不使用网页图案替代原生 renderer。

### 4.2 内容选择与专用设置

默认展示“内容”“设备/目标（适用时）”“显示方式/内容设置”“外观”。选择内容时提供名称、图标及一句用途说明，只列当前元素支持的已注册呈现。内置内容数量少，第一版采用轻量原生选择入口，不增加商店、安装列表或强制搜索步骤。

内容设置由注册的能力决定。没有适用行为时不显示一整张“没有可编辑行为”空卡。选择“无”时显示清晰的隐藏说明，并隐藏无效设置。

外观仍是元素级共享设置。首选/备用共用尺寸与既有配色规则，不新增备用专属尺寸。颜色状态只显示 renderer 实际可达的语义，不为了填充选项而增加虚假状态。

### 4.3 当前显示与当前编辑分离

左侧只保留一份当前选中元素的解析说明：真实来源、可用值和必要原因。正常时简洁显示；使用备用或异常替换时展开原因。通过解析结果生成，不能用“配置首选来源”的名字冒充当前显示来源。

右侧编辑首选内容时直接显示其具体名称。编辑备用内容时显示“编辑备用内容：Mac 电池”，避免只有“首选/备用”的抽象切换。切换编辑目标本身不改变真实来源顺序，也不强制改变实时数据。

保留实时/模拟模式显著标识。左侧说明去重；菜单栏和 Dock 预览不分别重复同一段状态文字。省略字段的来源不虚构实时数值。

### 4.4 备用和提醒

“不可用时”使用可折叠区域，收起时保留摘要，例如“显示 Mac 电池”或“隐藏”。展开后可以选择/删除备用内容、编辑备用专用行为和交换首选/备用；操作语义与现有配置保持一致。

需要配置备用设备时，其目标选择必须处于备用区域内且有明确来源标题。修改目标、行为或颜色均进入现有撤销事务。

网络异常优先规则位于中心的“提醒与切换”，不夹在输入法/电池/蓝牙自身设置里。它仍是单一全局开关，保持开关值和异常恢复语义，避免 UI 重排改变实际行为。

蓝牙权限缺失、设备未绑定等必要修复入口应靠近内容选择，不因高级区域折叠而不可见。后台读取维持现有明确同意要求，选择来源或打开编辑器不自动授权/启用。

### 4.5 操作与尺寸

继续即时生效，不新增“应用”按钮。保留撤销及键盘快捷键。恢复当前元素显示具体名称；恢复全部放更多菜单，保留确认与撤销。预设只保留既有能力，不在本轮扩展为方案管理系统。

中心尺寸 100–180%、外环/底部描边 80–120%、外环文字 90–110%，均以 5% 递增；遵守 `docs/icon-sizing-standard.md` 的旧值投影和显式编辑语义。

默认展开当前内容设置和外观。备用折叠状态按元素保留为当前编辑会话状态，不写入图标配置，不进入撤销历史。

## 5. 模拟与监控

插件声明所需样例，宿主聚合首选、备用和规则依赖，按来源去重。同一 Mac 电池用于两处时仍只有一份样例。模拟模式使用共享内存 session 和真实解析器，不影响 defaults、撤销或真实菜单栏/Dock。

模拟编辑器继续使用独立 NSPanel。选择内容或折叠备用不清空样例；关闭/隐藏窗口按既有生命周期停止预览动画。已有场景快捷填充继续可用。

监控声明描述“需要什么”，实际启动/释放由宿主统一处理。首选/备用依赖按现有策略聚合；多元素使用同一来源不会重复开启监控，移除最后一个使用者才释放图标持有的需求。不得释放其他窗口或功能持有的 owner token。

## 6. 验收

1. **插件接入**：所有当前可选内容都由注册器导出；实际解析、预览与需求聚合经过注册模块。通过测试内注入一个无生产实现的假插件，验证注册器契约及组合分发；假插件不进入用户界面。V1 存储兼容映射单独验证，不声称假插件已经支持持久化。
2. **行为与兼容**：现有配置加载不新增写入；旧 payload、颜色、统一尺寸、设备绑定和静态图案保持兼容。主/备用、双耳/单耳/离线、网络覆盖与恢复、未知/错误注册均有对应验收。
3. **编辑操作**：当前显示与当前编辑来源清楚分离；备用设置可折叠且可编辑；只出现一份解析说明；无效控件隐藏；交换、恢复、连续滑动和撤销保持正确范围。覆盖 12 语言和来源名称的辅助功能。
4. **渲染与生命周期**：对相同输入比较重构前后 scene/渲染，覆盖菜单栏及 Dock、深浅色、中心主/备用尺寸和严格墨迹居中。模拟隔离、监控去重/释放、两个窗口和减少动态效果均需验证。
5. **工程验证**：按变更运行 focused tests、`swift test`、`swift build -c release` 和 `swift test --filter Issue30WiFiAlignmentTests`；本地 Dev 界面验收注明实际测试内容。涉及 SwiftUI bindings/actor/generics 等时，合并或发布前必须通过项目规定的非发布 release CI；实际硬件读数与系统权限验收不能由模拟代替。
