# Status Trio 后台 Computer Use 接入

本文说明当前接入规则。历史实验、源码路径和原始验证记录保留在
[英文接入文档](background-computer-use-testing.md)；这些历史记录不代表本次重新做过真实 UI 验证。

## 职责边界

[background-ui-testing skill](../.agents/skills/background-ui-testing/SKILL.md)
只负责后台执行：绑定测试目标，评估启动、连接、读取、截图、放置窗口及输入的副作用，
观察干扰，停止不安全操作，以及清理本次拥有的资源。

测试什么、如何测试、用什么断言、怎样判定功能通过以及怎样报告，
由 Status Trio、开发者及其 AI agent 和测试工具决定。
不需要为了使用 skill，额外切换设置、导航页面、截图或先写完整测试计划。
已有的项目测试可以保留，不必删除，也不必每次重跑。

skill 是执行指引，不是驱动，也不提供独立输入会话。
第二块显示器只改变窗口位置，不能隔离焦点或输入。
仅审查代码和文档、运行非 GUI 检查时，不启动或连接应用。

## Status Trio 自己的接入选择

以下是本项目的约定，不是其他项目必须照搬的通用规则：

1. **默认走后台。** 操作或观察真实 Status Trio UI 前，读取项目内的 skill。
   测试目标必须是身份可核验、仍在本次任务授权及资源归属范围内的实例。
   可以复用符合条件的现有 Debug 后台测试实例；仅在需要启动或重建时使用项目启动器。
   其他应用应走各自支持的入口。
2. **保留项目启动器。** `bash scripts/launch-computer-use.sh [--display secondary] [--panel]`
   以分支独立开发身份构建并启动 Debug 测试实例。
   加 `--panel` 时改为打开状态面板，不打开设置窗口。
   该命令中的方括号表示可选参数，不是直接复制执行的字符。
   新启动遇到任何既有实例或 Bundle ID 冲突都拒绝，不自动退出进程。
   `--reuse` 只读核验并返回既有测试实例的身份，不构建、不发送 reopen，
   也不因此获得清理归属。需要重建时，由仍有权限的实例所有者先退出它。
   Debug 后台参数非法时，在创建应用环境或展示窗口前拒绝启动；
   Release 忽略后台测试参数。未连接副屏时会回退，不能声称覆盖了副屏。
3. **保留工具限制。** Codex 原生 CU、`kimi-cu` MCP、`agent-desktop`
   及其他限定实例的 AX/DOM/窗口接口都是候选工具。
   必须检查当前会话实际暴露的版本、模式和具体操作，不能凭工具名认定支持后台。
   尊重用户或项目指定且当前可用的工具。
   本项目禁止前台或全局输入，也禁止 `osascript`/System Events、
   `CGEventPost`、`cliclick` 和逐像素指针自动化。
4. **观察实际覆盖范围。** 可以复用适用的限时观察。
   `scripts/measure-ui-focus.swift` 记录前台身份、目标活动状态与策略、
   窗口边界及激活事件；它不能证明键盘路由、指针、剪贴板或全部工作区行为。
   把操作时间与记录区间关联，明确采样间隙及未覆盖维度。
   可用 `--pid <pid>` 指定预期目标；否则等待启动后绑定第一个唯一实例。
   目标退出、更换或出现多个匹配实例时结束覆盖并返回失败，不把后续时间算成连续观察。
   记录过期时先续上观察，不因此重启应用或重复功能测试。
5. **停止和清理有边界。** 不确定能否安全定位、操作会激活应用或需要全局输入时，
   停止受影响步骤；不能先激活再恢复焦点。
   前台或人工回退需要相应授权，其他独立且安全的工作可以继续。
   只恢复仍归本次所有的修改，释放本次清理范围内的资源，保留用户及其他 agent 的并发改动。

## 状态面板后台测试

`--panel` 只在 Debug 后台测试模式生效，必须与 `--background-ui-testing`
一起使用。该路径会跳过首次引导，不打开设置窗口，不会把面板设为 key window，
使用普通窗口层叠顺序，不安装失焦或全局点击关闭逻辑，并给面板一个标准 AX 窗口身份，
便于按窗口读取和操作。单显示器下前台应用会盖住面板；需要肉眼操作时使用副屏，
或按窗口截图/读取 AX。
面板原有按钮、开关和滑块的 accessibility label/value 保留。
已验证 AXPress 可切换静音并恢复，滑块也可通过 AX 数值写入。
当前 `agent-desktop set-value` 对本项目自定义滑块会发送字符串，AppKit 会拒绝；
滑块修改需用数值 AX 写入或项目侧测试辅助脚本。
这个结果只覆盖 Debug 后台路径，不代表正常打开面板的行为。

## 已知限制与结果表述

在后台模式下，不启用以下两个控件：蓝牙页的“在状态面板中显示”，
以及状态面板页的蓝牙可见性开关。它们仍显式激活应用，即使权限已经授予。
本项目对这些后台步骤沿用 `NOT RUN`，不为让测试通过而改权限行为。

历史上部分设置和首次引导的 AX 操作成功，不意味着菜单栏、真实 Dock 点击、
文本输入、快捷键录制、系统弹窗或其他工具也已支持。
未知副作用应通过已有文档、只读证据或另行授权的隔离校准解决，
不能在用户工作的会话中试探。

沿用项目已有报告约定，不增加 skill 专属状态名或模板。
例如，没有任何 CU 工具暴露给当前会话时，受影响输入步骤仍按本项目约定记为
`BLOCKED (no Computer Use provider)`，写明检查过的工具及连接后可解锁的操作。
工具已暴露但某条路径不安全时，写明具体原因。
功能结果与后台干扰结论应区分，缺少观察证据不等于零干扰。

## 普通测试为什么会出现 UI 闪现

现有一部分测试会真正显示设置、引导或状态面板，或创建系统菜单栏图标。
替换激活策略只能拦截策略调用，不能拦截 `makeKeyAndOrderFront`、
`NSApp.activate` 或真实窗口的 `orderFront`。不抢焦点也不等于不会出现窗口。
这些路径由测试代码直接执行，不能靠 CU skill 指令自动约束。

目前 18 个包含这类夹具的测试套件增加了显式执行边界：
XCTest 使用 `VisibleUITestCase`，Swift Testing 使用 `VisibleUITests.isEnabled`。
原有功能断言保留，默认跳过这些套件，非 UI 测试继续运行。
直接执行 `swift test` 也遵循该边界，不依赖调用者必须经过 shell 包装。

需要真实显示才能成立的用例，必须在另行授权的可见会话或适用的隔离环境中，
显式设置 `STATUS_TRIO_ALLOW_VISIBLE_UI_TESTS=1` 后执行。
该变量只解除执行限制，不提供后台能力或焦点隔离；不能为了消除跳过而直接启用。
`full` 验证也沿用默认边界，其通过不表示这些实机用例已通过。

本次修复增加了启动器只读复用的离线用例，以及目标等待、绑定、退出、
更换、PID 复用、歧义和预期 PID 的观察逻辑回归检查。
没有为运行 skill 新增控件切换、页面导航或截图门槛。
