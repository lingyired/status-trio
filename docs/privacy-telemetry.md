# Status Trio telemetry and privacy

Status Trio can send an occasional heartbeat to its first-party service at
`https://telemetry.lingai.net/v1/ping`. It helps estimate how many installations
are active and which app versions, macOS versions, languages, and icon locations
are in use. It does not record clicks, pages, popover openings, or other behavior.

## Your choice

On a new installation, the onboarding guide offers anonymous usage statistics,
with the switch off by default. No request is sent unless you turn the switch on
and finish the guide or choose **Customize**. Closing the guide leaves the
choice undecided; it will be shown again at the next launch. You can change the
choice in **Settings → General → Privacy and analytics**.

An upgrade from an earlier version starts with statistics off. Opening the guide
again does not turn them on. Ineligible builds also do not send telemetry:
development and debug builds are excluded, and a release must carry the
production marker set by the release workflow.

Turning statistics off stops future heartbeats. It does not remove information
already received by the service. The client keeps its random installation ID
and send timestamps so turning statistics back on continues the same
installation record. There is no client-side request to erase server records;
contact the project if you want to ask about an existing record.

## What a heartbeat contains

The JSON request has these required fields:

| Field | Meaning |
|---|---|
| `schema_version` | Payload format version (`1`) |
| `app_id` | Application identifier (`status-trio`) |
| `install_id` | A random UUID generated by this installation and kept across app updates and consent changes |
| `app_version` | Current app version |

The client may also send the app build, `macOS` and its major/minor version,
CPU architecture (`arm64` or `x86_64`), distribution (`github`), the preferred
system language, the language selected in the app, and the icon location
(`menuBar`, `dock`, or `both`). Empty or invalid optional values are omitted.
This release client declares its distribution as `github`, identifying the
binary artifact origin rather than where you acquired it. The app cannot tell
whether the GitHub-hosted artifact reached you through a mirror or package
manager. The client does not send a timestamp; the service uses its own receipt
time.

The payload has no field for a person's name, email, account, device name or
serial number, hardware UUID, Wi-Fi network, Bluetooth device, location, or
precise coordinates. The app uses no third-party analytics SDK. A heartbeat is
best effort, has a 2.5-second timeout, and does not block launch or app features.
The reporter checks on launch, wake, and every six hours; successful sends are
limited to at least 20 hours apart, so normal use is about once a day. Failed
attempts cool down for six hours.

## How the service handles it

The UUID is a stable, random installation identifier, not a hardware identifier.
The service does not store the raw `install_id`. It derives an app-scoped
HMAC-SHA-256 pseudonym from `app_id` and `install_id` using a server secret.
The pseudonym remains linkable across heartbeats for this app, so this is
pseudonymous data, not a promise of unlinkable anonymity. App-scoped hashing
prevents the same UUID from being correlated across different apps on the
service.

The service stores the latest installation state and per-day activity. Its
scheduled job removes `daily_activity` rows older than 365 days. The current
`install_state`, including its first and last seen times, and download snapshots
are not pruned by that job. The server records `first_app_version` from the
first heartbeat it accepts for an installation. That is the **first observed
version**, not necessarily the version first installed; older rows where that
column did not exist remain unknown.

The service endpoint is public so eligible clients can submit heartbeats. The
public statistics API and dashboard are separately disabled by
`STATS_PUBLIC=false`; that setting does not block heartbeat ingestion. Anyone
can forge a ping, so observed-install counts are estimates. The service uses a
more conservative established-install count requiring sightings on at least
two distinct UTC days, but this still cannot prove a ping came from an actual
installation.

Cloudflare and the network providers must process a connection's source IP to
deliver and rate-limit the request. The app does not put an IP address in the
payload, and the Worker does not persist the rate-limiter IP in its database.

Turning telemetry off or uninstalling the app both stop future heartbeats, so
the service cannot tell those cases apart. An installation that has not sent a
heartbeat recently is counted as inactive after it falls outside an activity
window; that does not mean it was uninstalled. Turning telemetry off does not
retroactively erase previous daily activity or the installation state.

## Language reporting

`os_language` captures the first preferred system language after normalization;
`app_language` captures the language Status Trio actually displays. Keeping both
distinguishes, for example, someone whose system language is Thai but who sees
the app in English from someone whose system and app are both English. The app
ships these twelve UI languages: `ar`, `de`, `en`, `es`, `fr`, `it`, `ja`, `ko`,
`pt-BR`, `ru`, `zh-Hans`, and `zh-Hant`.

For a fixed list of system-language tags outside that supported set, use this
query against the service's `install_state` table:

```sql
SELECT os_language, COUNT(*) AS audience
FROM install_state
WHERE app_id = 'status-trio'
  AND os_language IS NOT NULL
  AND os_language NOT IN (
    'ar', 'de', 'en', 'es', 'fr', 'it', 'ja', 'ko', 'pt-BR', 'ru',
    'zh-Hans', 'zh-Hant'
  )
GROUP BY os_language
ORDER BY audience DESC;
```

To inspect cases where the system and app languages differ, run this separately:

```sql
SELECT os_language, app_language, COUNT(*) AS installs
FROM install_state
WHERE app_id = 'status-trio'
  AND os_language IS NOT NULL
  AND app_language IS NOT NULL
  AND os_language <> app_language
GROUP BY os_language, app_language
ORDER BY installs DESC;
```

A mismatch is not necessarily an error: someone can choose an app language
different from the system preference. These queries describe aggregate counts;
they do not identify individual people.
